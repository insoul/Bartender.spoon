# Bartender.spoon 설계

macOS 27(Golden Gate)의 메뉴바 오버플로(`«`)를 이용해, 사용자가 고른 메뉴바 항목만 접는
Hammerspoon Spoon. 접힌 항목을 보는 것은 시스템 `«` 버튼이 담당한다. 이 Spoon 은 "무엇을
접을지"만 제어한다.

## 배경: macOS 27 메뉴바 동작 (2026-09-16 실측, 27.0 26A428)

- 메뉴바 항목이 예산을 넘으면 시스템이 **왼쪽부터 순서대로** `«` 오버플로로 접는다.
- `«` 와 `»` 는 시스템 프로세스 MenuBarAgent 의 **같은 버튼 하나**이고, AX description 으로
  상태를 구분한다. 접힌 항목이 있으면 `«` = "Show Hidden Menu Bar Items", 없으면
  `»` = "Hide Menu Bar Items". 버튼의 x 는 두 상태에서 같다.
- 항목 하나가 너무 넓어 들어가지 못하면 그 항목만 접히고 나머지는 되돌아온다.
  내장 1512pt 화면에서 구분자 폭 200 은 왼쪽 항목을 밀어냈고, 400 은 구분자 자신까지 접혔고,
  800 이상은 구분자만 접히고 나머지가 전부 복귀했다.
- 거대한 폭(10000 등)으로 항목을 화면 밖으로 밀어내는 방법은 쓸 수 없다. 시스템이 그 항목을 접는다.
- **여유를 넘는 폭을 주면 시스템이 메뉴바를 다시 배치하지 않는다.** 항목의 AX 폭만 요청대로
  커지고 구분자의 x 와 다른 항목의 x 는 폭 0 일 때 값 그대로 남는다. 내장 1512pt 화면에서
  약 600 이상이 이 구간이었다. 판독값만 보면 "아직 이웃이 보인다"로 읽혀 폭을 더 키우게 되므로,
  구분자가 요청한 만큼 왼쪽으로 움직였는지로 이 구간을 가려낸다.
- 구분자를 상태 영역의 오른쪽 끝 가까이 두면 폭을 키워도 오버플로가 걸리지 않는다. 왼쪽 항목이
  노치 뒤와 앱 메뉴 뒤로 밀려 그냥 가려지고 `«` 로 꺼낼 수 없다. 탐색은 이 경우 접힘을
  감지하지 못해 폭 0 으로 끝낸다.
- **접힘 판정**: 항목의 AX x 좌표가 `«` 의 x 보다 작으면 접힌 것이다. 실측한 모든 폭에서 일치했다.
  접힌 항목의 window frame 과 AX 좌표는 옛 값을 유지하므로 좌표 자체로는 판정할 수 없고,
  반드시 `«` 와 비교해야 한다.
- "디스플레이마다 별도 Space" 가 꺼져 있으면 메뉴바는 주 디스플레이에만 뜬다. 이 맥이 그 설정이다.
- `hs.menubar` 항목에 `hs.canvas` 로 만든 투명 이미지를 `setIcon` 하면 이미지 폭이 항목 폭이 된다.
  실제 항목 폭은 시스템 여백 때문에 **이미지 폭 + 18pt** 다.
  autosaveName 을 주면 ⌘+드래그 위치가 재시작 후에도 유지된다.
- `setTooltip` 의 문자열은 AX `AXHelp` 로 실린다. 구분자 식별은 이것만 쓴다.

이 동작은 문서화된 API 가 아니라 27.0 첫 빌드의 관찰 결과다. OS 업데이트 후에는 재검증한다.

## 사용법

1. Hammerspoon 이 구분자(투명 항목)를 메뉴바에 만든다.
2. 사용자가 ⌘+드래그로 구분자와 다른 항목을 배치한다. 구분자 **왼쪽 = 접힘**, 오른쪽 = 표시.
3. 접힌 항목을 보려면 시스템 `«` 를 누른다.

설정 파일, 단축키, UI 는 없다.

## 구성 요소

### 구분자 (`sep`)
- `hs.menubar.new(true, "bartender_sep")` 하나. 아이콘은 `hs.canvas` 로 만든 alpha 0.001 의 사각형.
- `setWidth(w)`: 폭 w 의 투명 이미지를 만들어 `setIcon`. w=0 이면 폭 1 이미지(항목 유지, 사실상 보이지 않음).

### 판독기 (`probe`)
- 모든 실행 중 앱의 `AXExtrasMenuBar` 자식을 모아 `{key, x}` 목록으로 만든다 (`hs.axuielement`).
  `key` 는 `pid:자식 인덱스` 다 — 제목은 시계처럼 매 초 바뀌는 것이 있어 못 쓴다.
- 메뉴바 버튼의 세 상태를 구분해 담는다.
  - `«` 있음 → `chevronX = 그 x`. 접힌 항목이 있다.
  - `»` 있음 → `expanded = true`. 사용자가 펼쳐 둔 상태다.
  - 버튼 없음 → 둘 다 없음. 여유가 많아 접힌 것이 없을 뿐이다. 폭을 키우면 `«` 가 생긴다.
- 구분자 자신은 `sep:setTooltip("bartender_sep")` 로 붙인 툴팁을 AX help 속성에서 찾아 식별한다.
  툴팁은 항목 폭에 영향이 없다.
- `isHidden(item)`: `«` 가 있고 `item.x < «.x`.

### 탐색기 (`fit`)
목표: 구분자 바로 왼쪽 항목은 접히고, 구분자는 보이는 **가장 작은 폭**.

0. **먼저 지금 폭 그대로 판독해 상태를 점검한다.**
   - `expanded`(`»` 있음) 면 아무것도 바꾸지 않고 끝낸다. 사용자가 펼쳐 둔 것을 다시 접지 않는다.
     버튼이 아예 없는 상태는 여기에 해당하지 않는다 — 접힌 것이 없을 뿐이므로 평소대로 판단한다.
   - 구분자가 보이고 구분자 왼쪽에 보이는 항목이 없으면(`satisfied`) 지금 폭을 그대로 둔다.
     폭이 필요 이상으로 넓어도 다시 재지 않는다 — 구분자 오른쪽은 먼저 접히지 않으므로 무해하고,
     매 트리거마다 폭 0 을 거치면 메뉴바가 1~2초 깜빡인다.
   - 지금 배치의 **서명**이 직전에 탐색이 실패한 배치의 서명과 같으면 건너뛴다. 배치가 그대로면
     결과도 그대로다. 서명은 구분자와 항목을 x 순으로 늘어놓은 key 목록에 상한을 이어 붙인
     문자열이라, 항목이 생기고 사라지는 것도 구분자가 자리를 옮긴 것도 잡힌다.
     서명은 항목 순서·개수·상한만 담는다. 같은 배치에서 항목 폭만 바뀌어 만족 가능해진 경우는
     잡지 못한다 — 폭을 서명에 넣으면 시계·배터리처럼 폭이 흔들리는 항목 때문에 헛탐색이
     되살아나기 때문이다. 항목 추가·삭제나 구분자 이동으로 풀린다.
     판단이 선 경로(만족·수렴)만 기억을 지운다. 펼침 상태나 구분자를 찾지 못한 경우처럼
     아무것도 알아내지 못한 경로는 기억을 그대로 들고 간다.
   - 위 어느 것에도 걸리지 않으면 아래 전체 탐색을 돈다.
1. 폭 0 으로 두고 판독. `«` 왼쪽 항목이 있으면 그것들은 어차피 접힐 것이므로 무시한다.
   구분자보다 왼쪽에 보이는 항목이 없으면 폭 0 으로 끝낸다.
2. 출발점을 정한다. 우선순위는 (a) 같은 항목 구성(`fit.keyset`: key 집합, 순서·좌표 무관)에서
   지난번 성공한 폭(`opts.hint`) — 맞으면 한 걸음에 끝난다. (b) 없으면 추정치: 구분자가 보이는
   상태면 `지금 폭 + 왼쪽에 보이는 항목 폭 합(AXSize) − 20`, 구분자가 접혀 있으면 폭 0 으로
   내려가 다시 재고 `폭 합 − 20`. 여유 공간은 읽을 수 없고 배치마다 0~40pt 로 달라(실측 36, 3)
   중간값을 뺀다. 구분자가 보이면 폭 0 을 거치지 않으므로 메뉴바가 덜 흔들린다.
3. 출발점에서 판정한다. 판정은 셋 중 하나다: `wide`(구분자가 접혔거나 폭이 반영되지 않음 —
   구분자가 왼쪽으로 `w/2` 만큼도 움직이지 않았으면 반영 안 된 것, 8pt 미만은 검사 안 함),
   `narrow`(왼쪽에 아직 보이는 항목 있음), `ok`. 어긋난 방향으로 걸음을 4, 8, 16… 두 배씩
   늘리다가 반대 판정이 나오면 그 사이만 이분한다. `ok` 가 나오면 빈칸을 최소로 하려고 같은
   방식으로 아래로 내려가며(`shrink`) 더 작은 `ok` 를 찾는다. hint 가 바로 `ok` 면 줄이지 않는다.
   실측: 캐시 적중 1걸음, 추정 17pt 오차에서 9걸음.
4. 브래킷이 1pt 로 좁혀지도록 `ok` 가 없으면 만족 구간이 없는 것이다 — 폭 0 으로 두고
   `hs.printf` 로 남기며, 이때의 서명을 함께 돌려주어 호출자가 보관한다. 다음 호출은 0 번
   항목에서 이 서명을 본다. 성공한 폭은 호출자(`init.lua`)가 `widthCache[keyset]` 에 기억한다.

   만족 구간은 왼쪽이 다 접히는 폭부터 구분자 자신이 접히는 폭 직전까지인데, `«` 는 항목
   경계 단위로만 움직여서 왼쪽이 다 접힌 다음 경계가 구분자 오른쪽 끝이다. 메뉴바가 빡빡하면
   이 구간이 몇 pt 에 불과하다(실측 120 이상 125 미만). 그래서 판정을 1pt 단위로 한다.

   구간이 좁다는 것은 결과도 그만큼 아슬아슬하다는 뜻이다. 오른쪽 항목 폭이 몇 pt 만 늘어도
   구분자가 접히고 왼쪽이 되살아난다. 그러면 다음 트리거가 만족 점검에서 걸려 다시 탐색한다.
   여유를 두고 싶으면 사용자가 항목을 더 접거나 끄면 된다.

각 단계의 정착 대기는 고정 시간이 아니다. 재배치는 애니메이션이라 걸리는 시간이 일정하지
않으므로, 100ms 마다 판독해 구분자·`«` 위치와 항목 수가 두 번 연속 같으면 안정으로 본다.
최대 1초를 넘기면 그대로 진행한다.

시스템 항목(배터리 등 MenuBarAgent 의 것)은 접히면 AX 목록에서 아예 사라진다. 그래서
`pid:index` key 가 밀리며, 탐색은 특정 항목의 key 를 따라가지 않고 "왼쪽에 보이는 항목이
있는가"만 본다.

탐색 중 하나의 실행만 허용한다. 실행 중에 요청이 오면 끝난 뒤 한 번 더 돈다.
`start()` / `stop()` 은 세대 카운터를 올린다. 대기 중이던 탐색은 깨어나서 세대가 바뀐 것을 보면
즉시 끊어, 다시 `start()` 한 뒤 옛 탐색과 새 탐색이 겹치지 않게 한다.

**Hammerspoon 타이머는 참조를 잃으면 GC 로 사라지므로 모든 타이머를 `self` 에 보존한다.**
정착 대기(`settleTimer`), 디바운스(`debounce`), 보정(`correctiveTimer`), 감시견(`watchdog`)이
모두 여기에 해당한다. 보존하지 않으면 콜백이 영영 오지 않아 코루틴이 깨어나지 못하고
`running` 이 참인 채로 굳어 이후 트리거가 전부 막힌다.

그래도 멈추는 경우를 대비해 **감시견**을 둔다. 탐색 시작과 함께 15초 타이머를 걸고, 정상
종료하면 거둔다. 발화하면 세대를 올려 낡은 코루틴을 끊고 `running`·`pending` 을 되돌린 뒤
다시 `schedule()` 한다.

### 트리거
- `hs.screen.watcher` — 주 디스플레이·해상도 변경
- `hs.application.watcher` — launched / terminated / activated
- `hs.timer.doEvery(60, ...)` — 앱이 자기 항목 폭을 바꾼 경우의 보정
- 세 경로 모두 `schedule()` 을 부르고, `schedule()` 은 0.5초 디바운스 후 `fit()` 을 호출한다.

### 잠금·절전
잠금 화면과 절전 중에는 메뉴바에 `«` 가 생기지 않는다. 구분자를 상한까지 키워도 아무것도
접히지 않아 탐색은 반드시 "만족하는 폭 없음"으로 끝나고, 그 실패가 서명으로 남으면 잠금을
푼 뒤에도 같은 배치에서 탐색을 건너뛰어 접기가 풀린 채로 남는다.

- `hs.caffeinate.watcher` 로 상태를 따라간다.
  `screensDidLock` / `screensDidSleep` / `systemWillSleep` 에 중단으로 들어가고,
  `screensDidUnlock` / `screensDidWake` / `systemDidWake` / `sessionDidBecomeActive` 에 나온다.
- 중단 중 `fit()` 은 로그 한 줄만 남기고 폭을 그대로 둔다.
- 돌아올 때 실패 서명을 버리고 다시 맞춘다.
- 이벤트를 놓친 경우를 위해, `fit()` 은 앞에 있는 앱이 `loginwindow` 여도 중단으로 본다.

### 옮기기 (`placeRight`)

다른 Spoon 이 켠 시스템 항목을 구분자 오른쪽으로 옮기는 작업. 폭을 만지는 일은 모두 이 Spoon 안에
있어야 탐색과 경합하지 않는다 — 폭은 `fit` 코루틴이 소유하는 상태라, 밖에서 `setWidth` 를 부르면
탐색 도중 폭이 바뀌고 보정 타이머가 드래그 도중 다시 접는다.

- 진입하면 `abort()` 로 진행 중인 탐색·디바운스·정착 대기를 끊고(세대 +1) `running` 을 잡아
  트리거가 `fit` 을 끼워 넣지 못하게 한다. 끝나면 `schedule()` 로 넘긴다.
- 순서: (1) 항목이 나타나기를 1초 기다려 지금 폭에서 본다. 보이는 데다 구분자 오른쪽이면 끝 —
  폭 0 을 거치지 않으므로 깜빡이지 않는다. (2) 접혔거나 왼쪽이면 폭 0 으로 내려 정착을 기다리고,
  항목 프레임이 두 번 연속 같을 때까지 기다린다(막 나타난 항목은 움직이는 중이라 그 좌표를 잡으면
  드래그가 빗나간다 — 실측). (3) ⌘+드래그로 구분자 오른쪽 가장자리 + 4pt 에 놓는다. 빗나가면 한 번
  더. (4) 폭을 건드렸으면 되돌리고 실패 서명을 버린 뒤 `schedule()`.
- 드래그는 `hs.eventtap` 으로 ⌘ 를 누른 마우스 다운·이동 12걸음·업을 15ms 간격으로 보내고 마우스
  위치를 되돌린다. `usleep` 으로 0.3초 막지만 이벤트는 MenuBarAgent 가 받으므로 전달된다.
- 연달아 부르면 `placeQueue` 에 쌓아 순서대로 처리한다. 감시견 10초. 잠금·절전 중이면 하지 않는다.

**실측 (2026-09-17, 27.0 26A428)**

- 시스템 항목의 저장 위치 `NSStatusItem Preferred Position <이름>`(`com.apple.controlcenter`)은
  켤 때 읽히지 않는다. 값을 바꾸고 스위치를 8→2 로 토글해도, `killall ControlCenter` 뒤에도 항목은
  옛 자리에 놓이고 시스템이 값을 되쓰지도 않는다. 그래서 위치를 쓰는 대신 드래그한다.
- 항목은 (재)삽입될 때 자기 저장 자리가 다른 항목의 슬롯 안에 들어가면 그 항목 오른쪽에 놓인다.
  구분자 바로 오른쪽에 놓인 항목의 슬롯은 구분자의 저장 자리를 덮으므로, 구분자를 다시 만들면
  (Hammerspoon 리로드) 구분자가 그 항목 오른쪽에 들어가 항목이 접힌다. 숨겼다 다시 켜는 것은
  구분자를 다시 만들지 않으므로 자리가 유지된다. 구분자 저장 자리는 앱 defaults 에 보이지 않아
  고칠 수 없다 — Barback 이 `start()` 때 켜져 있는 항목을 `placeRight` 로 다시 확인한다.
- 폭을 0 으로 내리면 접혔던 시스템 항목이 다시 AX 목록에 나타난다. 구분자는 오른쪽 항목들이
  정하는 자리에 17pt 로 남고, 그 오른쪽 가장자리 + 4pt 에 떨어뜨리면 항목이 구분자 바로 오른쪽
  슬롯에 들어간다(Wi-Fi: 978 → 1027, 구분자 1040 → 1002).

## 배터리·Wi-Fi 를 필요할 때만 보이기

이 Spoon 의 일이 아니다. 상태에 따라 시스템 항목 스위치를 켜고 끄는 것은 별도 Spoon 인
Barback.spoon 이 맡는다. Barback 은 항목을 켜면 `spoon.Bartender:placeRight(식별자)` 로 구분자
오른쪽에 두고, 끄면 `spoon.Bartender:schedule()` 을 불러 배치를 다시 맞추게 한다.

## 파일

```
Bartender.spoon/
  init.lua            Spoon 본체 (sep, probe, 트리거, 코루틴 실행, placeRight)
  lib/fit.lua         폭 결정 로직 — hs.* 없는 순수 Lua (satisfied, signature, decide)
  lib/guard.lua       잠금·절전 판정 — hs.* 없는 순수 Lua
  lib/place.lua       옮기기 드래그 계획·판정 — hs.* 없는 순수 Lua (dragToRightOf, isRightOf)
  tests/run.lua       단위 테스트
  tests/fake_bar.lua  판독 결과를 흉내내는 가짜 메뉴바
  docs/design.md      이 문서
  README.md           설치·사용법
```

`~/.hammerspoon/init.lua` 에 `hs.loadSpoon("Bartender"):start()`.

## 테스트

- `fit` 의 결정 로직(다음 폭 선택, 종료 조건)은 판독 함수를 인자로 받는 순수 함수로 분리해
  가짜 좌표 표로 단위 테스트한다. 독립 lua 인터프리터가 없으므로 Hammerspoon 의 Lua 로 실행한다:
  `osascript -e 'tell application "Hammerspoon" to execute lua code "return dofile(\"<abs>/tests/run.lua\")"'`.
  테스트 코드는 `hs.*` 를 쓰지 않는 순수 Lua 로 유지한다.
- 실제 메뉴바 동작은 `screencapture -R0,0,<width>,30` 으로 수동 확인한다.

## 범위 밖

- 단축키로 전부 펼치기 / 자동 재접기 (필요해지면 `setWidth(0)` 토글로 추가)
- 여러 디스플레이에 메뉴바가 동시에 뜨는 구성 ("디스플레이마다 별도 Space" 켬)
- 접힌 항목의 미리보기·검색 등 Bartender 앱의 부가 기능
